# 재현 가능한 평가 프로토콜

1. `configs/validation.json`에서 개발·검증 조건을 정의합니다. 개발 지도는 기본 규칙의 실행 점검에 사용합니다. 검증 지도는 사전에 정한 4개 규칙 후보와 6개 고정 알고리즘의 선정에 사용합니다.
2. SHA-256으로 기본 시드, 분할명, 크기, 구조, 밀도, 비용 종류, 반복 번호를 결합하여 지도 시드를 만듭니다. dev·validation·test·pilot은 서로 다른 입력을 사용합니다. 한 지도의 모든 확장·시간 예산은 같은 map_id에 속합니다.
3. 검증에서 선정한 규칙과 단일 고정 기준선을 저장한 뒤 test 지도를 실행합니다. 최적 비용은 실행 전에 별도의 Dijkstra가 계산하지만 에이전트 입력에는 전달하지 않습니다.
4. 동일 지도·예산에서 모든 방법을 실행합니다. 실행 순서는 시드로 셔플하여 고정 순서의 영향을 줄입니다. 각 실행에서 유효한 경로와 확장 예산 준수를 확인합니다.
5. 시간 예산은 별도 pilot 지도에서 A*의 시간을 측정하여 보정하고 그 값을 저장한 뒤 고정합니다. `configs/time.json`의 test 지도를 시간 제한으로 다시 평가합니다.
6. 지도 단위 bootstrap으로 95% 구간을 계산합니다. 동일 지도의 예산 실행을 한 묶음으로 재표집합니다. 전체 결과, 조건별 결과, adaptive와 각 방법의 짝지은 차이를 저장합니다.

## 지도 구성

무작위 지도는 출발·도착을 제외한 칸에서 지정한 수만큼 장애물을 표본 추출합니다. 연결성을 강제로 보장하지 않습니다. 목표가 막힌 지도도 연구 결과에 남깁니다. 기본 출발·도착은 양 모서리입니다.

U자 지도는 시작점에서 목표로 향하는 직선 방향이 막히고 반대 방향 입구로 우회해야 합니다. 위치·폭·높이와 시작 행을 시드에 따라 달리합니다. 벽 지도는 여러 수직 벽에서 위·아래로 번갈아 좁은 통로를 두고 벽 시작 위치와 통로 위치를 무작위화합니다. 미로는 난수 DFS로 통로를 생성합니다. 구조 지도는 입력 밀도를 강제로 맞추지 않으며 실제 밀도를 기록합니다. 따라서 구조별 효과는 밀도까지 통제된 인과 효과가 아닙니다. 구조 변형의 다양성은 가능한 배치 범위에 한정됩니다.

가중 비용은 1, 3, 5를 각각 65%, 25%, 10%의 확률로 배정합니다. 출발점 비용은 경로 비용에서 제외하며 이후 도착 칸의 비용을 합산합니다. h0는 맨해튼 거리 × 통과 가능한 칸의 최소 비용입니다.

## 비교·제거 실험

| 이름 | 동작 |
|---|---|
| bfs / dijkstra / astar / greedy / weighted_* | 고정 탐색기 하나 |
| initial / no_switch | 지도·예산 기반 초기 선택 후 해당 탐색기만 실행 |
| equal | 고정 전략 6개에 같은 크기의 구간을 순환 배정; 완료된 전략의 몫은 재배분 |
| adaptive | 관찰 기반 전환, 최대 2회, 품질·정체 반환 |
| ara | 단일 상태를 재사용하는 ARA* |
| no_progress | 지도 특징으로 초기 선택, 남은 예산 비율에만 따른 전환 |
| no_early_return | 충분 품질·최적 인증·개선 정체 기반 조기 반환 제거 |
| unlimited_switches | 적응형 전환 횟수 상한 제거 |
| first_solution | 같은 초기 선택에서 첫 실행 가능 경로 확보 즉시 반환 |

`no_early_return`은 유용한 탐색기가 완료되거나 전환 가능한 전략이 없을 때 종료할 수 있습니다. 종료된 탐색기로 남은 예산을 의미 없이 소모하지 않습니다. 고정 탐색기는 첫 해를 찾거나 frontier를 소진하면 종료합니다.

## 시간과 메모리

전체 시간에는 특징 계산, 선택, 초기화, 전환, 경로 복원, 기록 및 상태 크기 추정이 포함됩니다. 지도 생성·평가 oracle·JSON/CSV 파일 저장·브라우저 애니메이션은 제외합니다. 시간 마감은 확장 전후에 검사하며 마감 후 완성한 새로운 경로를 채택하지 않습니다. 마지막 확장·초기화·결과 정리의 초과 시간을 별도 기록합니다.

기본 `peak_retained_estimate_bytes`는 유지하는 컨테이너 크기 및 항목 수를 기반으로 한 추정치입니다. `profile_memory: true`는 Python allocation peak를 실제 계측한 `peak_traced_bytes`를 추가합니다. 프로파일러 비용은 그 실행 시간에 포함합니다. 둘 다 OS RSS나 전체 프로세스 최대 메모리는 아닙니다. 작은 smoke 실험은 실제 계측을 켜고, 본 평가와 시간 실험은 켜지 않아 프로파일러가 시간 마감을 바꾸지 않게 합니다.

## 핵심 지표

`quality_ratio = C/C*`; `Sρ = 품질 비율 ≤ ρ인 성공 수 / 경로가 존재하는 전체 사례 수`입니다. ρ는 1.05, 1.10, 1.25입니다. 예산 내 경로 미발견을 Sρ의 실패에 포함하고, oracle에서 경로 없음으로 판정한 지도는 분모에서 제외합니다. 후자는 실제 탐색기가 경로 없음을 증명했는지도 따로 셉니다.

성공 사례의 평균 품질만으로 성능을 결론짓지 않습니다. 두 방법이 모두 성공한 사례의 품질 차이도 별도 계산합니다. 작은 pilot의 시간 보정과 bootstrap 500회는 예비 연구 수준이며 제출 연구에서는 반복 실행·더 많은 지도 및 2,000회 이상 bootstrap으로 안정성을 확인할 수 있습니다.

결과는 현재 하드웨어와 지도 분포에 대한 관찰입니다. 적응형이 불리한 조건도 결과로 남기며, 여러 비교의 95% 구간을 다중 비교 보정이 된 유의성으로 해석하지 않습니다.
